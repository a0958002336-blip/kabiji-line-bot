# 卡比集機器人 — 完整診斷報告（唯讀分析）

> 由 5 個唯讀代理精讀 `卡比集機器人.gs`（v2.57, 3130 行）產出。全部定位到行號，未修改任何程式。
> 日期：2026-07-02　CTO。

## A. 五大 Bug 根因（依嚴重度）

### Bug1（高）一般交易誤判為旭陽寄運
- **根因**：分派鏈末端「寄運出貨」保底條件（行535）只看「整段含 `\d+件/台/包/箱`」，`翠峰…中15件`命中；`parseShipping`（行835）逐行處理時，首行裸數字`1828`在行890被**無條件當客戶抬頭**寫入`寄運資料`（行547）。
- **事實澄清**：物流欄其實是空字串，程式沒主動標「旭陽」；是`寄運資料`表本身＝旭陽/主貨運帳，且`shippingPull('旭陽')`(行1100)客戶名比對會把它撈進旭陽底下顯示。
- **修**：Router 分類前置驗證「首行須為合法客戶/貨主、非純數字、寄運需物流關鍵字」。→ R1.1–R1.3

### Bug2（高，實為新建）收款後 #未收款 不消失
- **根因**：`#未收款`／`收款`／`收錢`指令**全檔不存在**。現行「匯款」(行615)只 `appendRow` 到`財務改價`(行2827)，從不對帳；`統整金額`(行2158)讀的是**另一張**`群組訊息`表加總`=金額`，且行2153**主動濾掉「匯款」**。兩份資料永不交會。
- **修**：需**新建應收/收款對帳**（收款沖銷 + `#未收款` 查詢 + schema）。屬新功能。→ R2.1–R2.3

### Bug3（高）取消功能失效
- **根因（雙重）**：①程式不讀 LINE 回覆上下文（行47–57 無 `quotedMessageId`），回覆取消時只收到孤立「取消」；②所有取消閘門要求同則文字自帶客戶/品名/數量（行460 `isShipping`、行938 `curCust`），孤立「取消」命中不了任何 handler，連錯誤提示都不回（靜默）。取消為實體`deleteRow`(行964)、無 log。
- **修**：讀 `quotedMessageId` + 落地訊息以反查原文；新增 取消+客戶代號、取消+流水號。→ R3.1–R3.4

### Bug4（高）錯誤打卡污染正式紀錄
- **根因**：打卡寫入前無驗證，任何「≤12字+下班」都被當員工名寫入正式`出勤打卡`(行490/502/2957)。「△(資料異常)」**不是程式判定**（全檔 grep `異常/△` 0 筆），而是當初被存進員工欄的字串，查詢原文照印(行3085)。
- **修**：員工白名單驗證 + 異常導入 `abnormal_logs` + 修正/刪除打卡指令 + 完整 log。→ R4.1–R4.5

### Bug5（中）清除/取消權限缺口
- **根因**：老闆檢查條件含 `&& OWNER_USER_ID`（行311等），未`#註冊老闆`時短路→管理群組內任何人可清除；外勤補貼清除(行162)無 isAdmin。→ R5.3
