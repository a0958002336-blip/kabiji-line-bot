## 二、全滅還原（假設電腦壞掉，從零救回）

情境：這台電腦壞了／檔案全沒了，只剩 GitHub 上的程式碼。目標＝在新電腦上把程式碼拿回來，並重新部署到 GAS。

### A. 先準備（新電腦）
1. 安裝 **Git**：到 https://git-scm.com/download/win 下載安裝（一路下一步即可）。
2. 確認能登入 **GitHub 帳號** `a0958002336-blip`（程式碼在這）。
3. 確認能登入機器人所屬的 **Google 帳號**（Apps Script 與試算表在這）。

### B. 把程式碼抓回來（clone）
1. 開「開始」→ 搜尋 **Git Bash** → 打開。
2. 依序輸入（一行一個 Enter）：
   ```bash
   cd ~/Desktop
   git clone https://github.com/a0958002336-blip/kabiji-line-bot.git
   cd kabiji-line-bot
   git checkout develop
   ```
3. 完成後，桌面會出現 `kabiji-line-bot` 資料夾，裡面的 `卡比集機器人.gs` 就是最新程式全文。
   - 若要求登入 GitHub，照畫面用瀏覽器授權即可。

### C.（建議）先確認測試全綠
> 需要 Node.js（https://nodejs.org 下載 LTS 版安裝）。非必要，但能確定抓回來的程式是好的。
```bash
node tests/golden/run_all.js
```
看到 `總計：235/235 通過` ＋ `✓ 全綠` 就對了。

### D. 重新部署到 GAS
1. 用 Google 帳號打開機器人的 **Google 試算表** →「擴充功能」→「Apps Script」。
   - 若連試算表都沒了：先從〈部署前備份〉的試算表副本另存一份回來，再開它的 Apps Script。
2. 打開 `卡比集機器人_repo/卡比集機器人.gs`（或 GitHub 上同名檔），**全選、複製全文**。
3. 回 Apps Script 編輯器，開對應檔案（通常 `Code.gs`）→ **全選(Ctrl+A)→刪除→貼上**→ **儲存(Ctrl+S)**。
4. 右上「部署」→「管理部署作業」→ 現有 Web 應用程式 → **鉛筆(編輯)** → 版本選「**新版本**」→「部署」。
   - ⚠️ 千萬**不要**按「新增部署作業」，否則會產生新網址、LINE 會斷線。
5. **若這是全新的 Apps Script 專案**（舊的也沒了）：
   - 需要重新設定兩個機密：`CHANNEL_ACCESS_TOKEN`、`OWNER_USER_ID` 等 → 在 Apps Script「專案設定」→「指令碼屬性」補回（值向 LINE Developers 後台與舊紀錄取得）。
   - 部署後把新的 Web App 網址填回 **LINE Developers → Messaging API → Webhook URL**。
6. 在 LINE 打 `#版本`，看到橫幅且 hash 顯示 `75651ce`（或更新後的值）＝ 還原成功 ✅。

### E. 資料還原（如需要）
- 若試算表資料毀損：打開〈部署前備份〉時建立的 `卡比集資料備份_YYYYMMDD` 副本，另存為正式試算表，或把資料分頁貼回。

## 三、回退上一版（新版出包，切回前一個部署版本）

> 只切「程式版本」，**不會動到資料**。這是出問題時最快的止血。

1. Apps Script 右上「部署」→「**管理部署作業**」。
2. 找到現有的「Web 應用程式」那一列 → 點右上角**鉛筆(編輯)**。
3. 「版本」下拉 → 選**前一個版本號**（部署前若有照〈部署手冊〉步驟 0-2 記下舊版號，就選那個）。
4. 按「**部署**」。
5. 回 LINE 打 `#版本` 確認行為回到舊版。
6. 把「哪一項失敗、你打了什麼、機器人回什麼」記下來回報工程端。

**（進階／有原始碼者）用 git 取回舊程式再貼：**
```bash
git checkout rc-4 -- 卡比集機器人.gs        # 取回 rc-4 的程式（或改成任一 tag）
# 或還原某個快照：backups/Code.gs.before-all、backups/Code.RC.gs
```
再照〈部署手冊〉步驟 1~3 貼上、部署。

## 五、啟用每日自動備份（dailyBackup）— 部署後做一次

> 程式已內建每日備份功能，但 Google 規定「自動排程」與「存取 Drive」需**由你在 GAS 手動啟用並授權一次**。做完就永久生效，不用每天管。

### 5-1 啟用步驟（約 2 分鐘，只需一次）
1. 打開機器人的 Apps Script 專案（試算表 →「擴充功能」→「Apps Script」）。
2. 上方**函式下拉選單**選 **`setupBackupTrigger`** → 按 **▶ 執行**。
3. 第一次會跳出**授權**視窗：選機器人所屬的 Google 帳號 →「允許」存取雲端硬碟（Drive）。
   - 若出現「Google 尚未驗證這個應用程式」→「進階」→「前往（不安全）」→ 允許（這是你自己的專案，安全）。
4. 再執行一次 `setupBackupTrigger`（若剛才卡在授權）。看到執行紀錄（Ctrl+Enter 開「執行紀錄」）顯示：
   - `✅ 已建立每日 dailyBackup 觸發器（約 23:30）。` → 啟用成功 ✅
   - 若顯示 `已存在 dailyBackup 觸發器，不重複建立。` → 代表之前已啟用，也 OK（不會重複）。

> 💡 本版**只需既有的試算表權限**、不使用 Drive 進階權限，所以理論上執行 `dailyBackup` 不會再跳 Drive 授權。若你的環境仍卡在授權，第 5-1 的 `setupBackupTrigger` 也只需一般授權即可。

### 5-2 立刻測一次（確認真的會備份）
1. 函式下拉選 **`dailyBackup`** → ▶ 執行。
2. 開「執行紀錄」，應看到 `✅ dailyBackup 完成：已複製整份試算表為「卡比集總管_backup_YYYY-MM-DD」…`。
3. 打開 Google 雲端硬碟的 **「我的雲端硬碟」根目錄**，應出現一份 `卡比集總管_backup_（今天日期）` 的試算表副本。
4. 若備份失敗，老闆的 LINE 會收到「⚠️ 今日試算表備份失敗…」通知；照通知檢查試算表是否存在／空間是否足夠。

### 5-3 它的行為
- 每天約 **23:30** 用「試算表複製」把整份試算表複製到 **我的雲端硬碟根目錄**（僅需既有試算表權限，不需 Drive 新授權）。
- 檔名：`卡比集總管_backup_YYYY-MM-DD`（例：`卡比集總管_backup_2026-07-08`）。
- **不會自動刪舊檔**（自動刪需 Drive 進階權限）。改為**每週一次**由老闆 LINE 收到提醒，請自行到雲端硬碟搜尋 `卡比集總管_backup_` 整理，建議保留最近 14 份。清理提醒失敗不會影響備份。
- 想改時間，請工程端改 `setupBackupTrigger` 的 `atHour/nearMinute` 後重新部署。

### 5-4 用每日備份還原資料
到雲端硬碟搜尋 `卡比集總管_backup_` → 挑要的日期 → 右鍵「建立副本」或「下載」→ 把資料貼回正式試算表（或另存為正式試算表）。
