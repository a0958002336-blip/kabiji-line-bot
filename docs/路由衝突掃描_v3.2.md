# 路由衝突掃描（v3.2，過夜工作 B）

> 方法：對 25+ 個模稜兩可/邊界訊息驅動 handleEvent，記錄「被哪個 handler 接走、寫哪張表」。
> 原則（過夜守則）：**只修有把握、不改變既有正確行為的**；其餘一律列此表待老闆決策，**未自行修改**。

## 一、需老闆決策（未修改）

### 🔴 C1（影響較大）：「客戶 台子*N」被記成**鐵架**，不是台子
- 實測：`陳記 台子*3` → 回「🔧 出鐵架…[A] 台子 ×3」，寫入**鐵架庫存**（rackId=「台子」），不是台子庫存。
- 同類：`大買家\n(台子*3)`（括號單）也一樣進鐵架庫存。
- 成因：`handleRackInlineOut`／`handleRackParenBatch` 把任何「名稱*數量」當鐵架；`rackEntryGuard` 雖對「純台子」放行，但 inline/paren handler 仍接走。
- 影響：這種台子出庫查「查台子」看不到、查「查鐵架」才看得到，且會被配鐵架代號。
- **屬既有行為（非 v3.1/v3.2 造成）**。正確台子出庫請用：`客戶\n品名 特 N件（台子）`（走寄運台子 pack，實測正確寫台子庫存）或 `台子×N 收M`。
- 建議（待決策）：是否要在 inline/paren handler 把 rackId=「台子」改寫到台子庫存？**有回歸風險**（牽動 rackNet／代號／查台子），故未自行修改。

### 🟡 C2：「數量=金額」但**沒有乘號**的計價單不會日期戳
- 實測：`10箱=5000` → 走寄運判讀 →「⚠️ 無法判斷指令」（該群未安靜時才會跳；安靜則靜默）。
- 成因：v3.2 計價單樣式規定要有乘號 `數量*單價=金額`；`10箱=5000` 無 `*`，不符樣式，故不日期戳、改走寄運未解析。
- 無資料風險（不寫任何表）。若老闆希望「純 數量=金額」也日期戳，需放寬樣式——但放寬會誤觸更多訊息，**待決策**。

### 🟡 C3：含「收款」二字的疑問句會跳收款提示（且不受安靜管制）
- 實測：`客戶收款人是誰` → 「⚠️ 偵測到收款意圖但讀不到金額…」。
- 成因：`recvDetect` 命中 RECV_KW「收款」但無金額 → needAmount 提示；此提示刻意不靜音（見 `docs/安靜模式警示點調查_v3.1.md`）。
- 低頻。是否要讓 needAmount 提示也尊重安靜，**待決策**（v3.1 調查已列同一項）。

## 二、經確認屬「設計如此」（不需修）
- `阿明 高麗菜 要收 6800` → 不建收款（靜默）。RECV_KW 已**刻意移除裸「要收」/「收」**避免誤判；正式請打「要收款 6800」。✅ 符合 D4/意圖守衛設計。
- `22包旭陽`、`300包`、`1828⏎50件`、`高麗菜特20件` → 「無法判斷指令」。屬不完整寄運片段，且**受安靜模式管制**（該群 `#安靜` 後靜默）。✅ 既有設計。
- `收款人 林義祥`（無未收款時）→「目前沒有未收款可指定」。✅ v3.1 正確。
- `K棧板*2收`、`ok 收到`、`a1收到了` → 靜默、不誤觸代號收回。✅ v3.2 前綴/雜訊防呆正確。
- `B*2收回`（代號不存在）→「查無未收回」。✅ 正確警示。
- 疑問語尾 `上班了嗎`、`退休金什麼時候發`、`匯率多少` → 靜默不寫入。✅ Task9 防呆正確。

## 三、結論
- **無「有把握且零風險」的修正**可自動施作——找到的衝突不是既有刻意設計（不該動），就是牽動 rackNet/寄運的高風險改動（C1/C2）。故本輪**未改任何程式**，全部列此表待老闆決策。
- 若老闆要處理 C1（台子*N 誤記鐵架），建議另開一次「照 Task 0 流程」小修：先加「台子*N inline → 台子庫存」測試（正/反＋查台子/查鐵架/rackNet 不受影響），再改 handler。
